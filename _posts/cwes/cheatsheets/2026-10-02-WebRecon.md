## Methodology

> `Start passive: WHOIS, DNS records, cert transparency, web archives, Google dorks.`
>
> Move to **DNS**: resolve records, then try a **zone transfer** for the whole namespace.
>
> 
> Enumerate **subdomains** passive first, then brute force (dns , vhosts).
>
> **Fingerprint** each live host: server, framework, WAF, Versioning.
>
> 
> **Crawl** for hidden content: `robots.txt`, `sitemap.xml`, `.well-known`, comments, archived URLs.
>
> Feed findings forward: subdomains and vhosts become new targets, versions become the exploit search, repeat lmao.



Methodology GDork:

> **Google dorking** is search operator abuse to surface **indexed files, panels, and secrets** a target never meant to expose.


## Enumeration

`Public attack surface of a domain`

```
site:<TARGET_DOMAIN>
```


`Login and admin panels`

```
site:<TARGET_DOMAIN> (inurl:login OR inurl:admin OR inurl:panel)
```


`Indexed files by type`

```
site:<TARGET_DOMAIN> (filetype:pdf OR filetype:xlsx OR filetype:conf OR filetype:sql)
```


`Exposed directory listings`   

```
site:<TARGET_DOMAIN> intitle:"index of"
```


`Config and env leaks`  

```
site:<TARGET_DOMAIN> (ext:env OR ext:ini OR ext:log OR ext:bak)
```


`Credentials in body text`

```
site:<TARGET_DOMAIN> intext:"password"
```


`Backups and dumps`   

```
site:<TARGET_DOMAIN> (filetype:sql OR filetype:bak OR filetype:zip) intext:"dump"
```


`Subdomains minus www`

```
site:*.<TARGET_DOMAIN> -inurl:www
```


`Third party leaks (pastebin, s3, drive)`   

```
"<TARGET_DOMAIN>" (site:pastebin.com OR site:s3.amazonaws.com OR site:drive.google.com)
```

## Crawling

> Crawling walks every reachable link from a root to map endpoints, parameters, and comments.
>
> 

`WAF detection`

```bash
wafw00f http://<TARGET_DOMAIN>
```

`Crawl using SpiderRecon:`

```bash
python3 SpiderRecon.py <TARGET_URL>
```

```bash
cat results.json | jq
```


### Virtual Hosts


:::info
Same IP, different Host header serves a different site. Filter by response size to spot the vhost that differs.

:::

`Fuzz the Host header on the resolved IP`

```bash
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt -u http://<TARGET_IP>/ -H "Host: FUZZ.<TARGET_DOMAIN>" -fs <BASELINE_SIZE>
```


## .well-known 


:::info
.well-known/ is a standardized URI prefix (RFC 8615) where sites expose metadata at predictable paths.

:::

==IANA registry of valid names:== [==https://www.iana.org/assignments/well-known-uris/well-known-uris.xhtml==](https://www.iana.org/assignments/well-known-uris/well-known-uris.xhtml)


Typical high-value:

```bash
curl -s http://<TARGET_DOMAIN>/.well-known/security.txt
curl -s http://<TARGET_DOMAIN>/.well-known/openid-configuration
curl -s http://<TARGET_DOMAIN>/.well-known/assetlinks.json
curl -s http://<TARGET_DOMAIN>/.well-known/apple-app-site-association
curl -s http://<TARGET_DOMAIN>/.well-known/mta-sts.txt
curl -s http://<TARGET_DOMAIN>/.well-known/host-meta
```

`Brutforce using:`

```bash
ffuf -w well-known-uris.txt -u http://<TARGET_DOMAIN>/.well-known/FUZZ -fc 404
```

Info:

```bash
security.txt                  contact, disclosure policy, sometimes internal paths
openid-configuration          full OIDC/OAuth endpoint map, issuer, jwks_uri
jwks.json / jwks_uri          signing keys for tokens
assetlinks.json               linked Android apps and package names
apple-app-site-association    linked iOS apps and deep link routes
mta-sts.txt                   mail transport policy, reveals mail hosts
host-meta                     XRD/host metadata, points to more endpoints
change-password               password change URL, hints at auth stack
```
